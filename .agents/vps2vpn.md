# vps2vpn：项目目标和已定的决定

这份文档记录用户定下的方向。后定的决定覆盖先定的。用户有新决定时，补在这里并写上日期。当前版本、正在做的事和待办见 `HANDOFF.md`。

## 项目是什么

- **客户端**：本仓库 `xydadada/vps2vpn-client`。基于 FlClash，主分支是 `vps2vpn`，上游的 `main` 不用来发布。目前只发 Windows 版，简易模式的页面在 `lib/vps2vpn/`。
- **服务端**：`xydadada/vps2vpn`，包括面板、部署器、会员中心和管理面板。它有自己的 `AGENTS.md`、`HANDOFF.md`、`docs/goals.md`。
- **两边解耦**：
  - 客户端在别家面板上也要好用，比如 V2Board、SSPanel 和普通的 Clash 订阅。
  - 我们服务端提供的功能只算增强。没有服务端时不报错、不留空白、不误导用户。
  - 客户端更新的主渠道是 GitHub Releases，面板的 clientsync 只是补充渠道。
  - 逐项归类见 `HANDOFF.md` 第 10 节。

### 用户认可的样子（1.0.27）

- 宽窗口，深色，背景有暖色光晕，侧边栏导航。
- 首页上方是一张大卡片：左边是状态和「智能线路」标题，右边是带光圈的电源键。
- 大卡片下面是 4 张数据卡：速度、流量、延迟和出口。
- 节点名形如「洛杉矶 · 5×」，流量是 TB 级。

用户自己的订阅来自别家面板，不是 vps2vpn 服务端。所以审截图时，除了看 CI 的干净数据，还要看「别家面板形状」的数据：节点名长、带倍率、流量是 TB 级、没有面板会员信息。

### 怎么改界面

- 一次只改一页或一类细节，在单独的分支上做。
- 截图由 `screenshots.yaml` 生成，要有中英文、深浅色、宽窗口、默认窗口、最窄窗口，以及 125% 和 150% 缩放的改前和改后截图。
- 主会话审过截图才合并。合并的顺序和状态见 `HANDOFF.md` 第 0 节。

## 已定的决定

- 不买 Windows 代码签名证书，安装包不签名。每个发布文件都要有更新签名 `.sig`，用 Ed25519。私钥只放在 GitHub secret 里，不进仓库，不轮换。
- 界面语言只留中文和英文。
- 用户还在用 1.0.27，它在别家面板上不会自动更新。用户选择手动安装 1.0.34。所以 1.0.34 转为 Latest 之前，`e2e.yaml` 的 gate 必须全部通过，其中 legend 这一项要从真实的 v1.0.27 升级。
- 维护者（AI）自己判断、审查、合并、发版，只有很重要的事才问用户。对用户说中文。
- 外部 AI 审查可以开 PR 和 issue，但不合并、不推 `vps2vpn`、不打 tag。我们逐条核实后自己写修复，不整体应用别人的补丁。
- 仓库设置由用户决定，例如开启私密漏洞报告（#150）。
- 上游 FlClash 留下的、对 vps2vpn 没用的东西可以删（2026-11-27 用户定）。`.agents/` 里其余的技术文档来自上游，描述的代码仍在使用，所以保留。但其中写到的上游 CI（`desktop` job、release matrix、Pages、Telegram、`vX.Y.Z-pre` 标签）在本仓库已经没有了，发布流程以 `HANDOFF.md` 第 2 节为准。
