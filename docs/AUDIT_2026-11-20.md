## 本轮补充发现：批量测试漏加载目录配置

位置：基线 tool/test.dart 的 _writeBundles（约 168 行）与 test/flutter_test_config.dart。

Flutter 从测试入口所在目录向上寻找最近的 flutter_test_config.dart，到 pubspec.yaml 停止。原入口在 .dart_tool/test_bundles，目录链不经过 test/，因此没有执行已有的 testExecutable，也没有设置 vps2vpnUpstreamUi。继承 Home/dashboard/navigation/tray 测试打开了简化界面，引出大量找不到控件和标签不符的失败；单独重跑却能加载该配置。这是测试路径配置不一致，不能据这些失败直接宣称相应产品控件损坏。

修复：生成 bundle 时，同目录生成一个仅 export 根测试配置的 flutter_test_config.dart。继续使用原配置、原 UI 断言、原失败重跑逻辑；没有跳过失败测试。带 @TestOn 的独立测试仍按原路径运行。

依据：[Flutter 官方测试配置规则](https://api.flutter.dev/flutter/flutter_test/)，2026-11-20 实时核对。对应验证是修复后完整 Flutter suite，而不是比较测试源文本的替代测试。

## 本轮补充发现：桌面打包产物名称不一致

基线 build_config.yaml:5,8 和 setup_hooks/options.dart:35,38 已将产物设为 vps2vpnCore / vps2vpnHelperService，Go/Rust builder 和运行时 AppPath.corePath 按这些名称工作。但 linux/CMakeLists.txt:113–114 仍安装旧的 FlClashCore / FlClashHelperService；macOS 的 Stage Core、PBX 文件引用与输出声明也仍为 FlClashCore。

实际 [Linux build job 136227304390](https://github.com/xydadada/vps2vpn-client/actions/runs/44718286674/job/136227304390) 在 CMake 安装阶段找不到 FlClashCore，证明干净构建不能成功。macOS 的同类错误由生产/消费路径交叉核对确认，尚未实际执行 Xcode。

修复仅将 Linux 两个产物名和 macOS 十处 Core 引用统一为当前 build_config.yaml 的名称，保留 lipo 架构校验、CodeSignOnCopy 和主应用现有名称。Windows CMake/Inno 已一致，macOS 原架构不生成 Helper，因此不额外添加产物。新增 desktop_artifact_contract_test.dart 的三个跨文件契约测试，从 build_config.yaml 读取期望名称，检查 Linux、Windows、macOS 的实际打包声明和 Stage 脚本。

原构建日志另有 File modified during build 提示；只有修复后真实构建才能确定是否仍存在，不能预先写成构建通过。

## 尚未解决及验证边界

### 合并前阻断：上游并发

锁定 Clash.Meta 5b453f80dbcee6b3ecfb0415bcace24a48c88707 的 hub/route/server.go 中，ReCreateServer 异步启动控制接口，start 在无锁情况下读写全局 httpServer。包装层 configMu 不能保护这些内部 goroutine。实际 race 在控制接口 secret 快速变更的现有测试中复现；普通功能通过不消除竞态。

已核对锁定 fork 与上游当前分支，没有找到可以直接更新 pin 的已修复版本。未修改外部仓库、未盲目升级、未禁用 race、未加 sleep 掩盖。需维护具有同步生命周期的依赖修复，并确保 CLI、mobile、setup hook、Makefile 和 CI 共同消费同一个已验证版本。

### 既存工程规范冲突

test/lint/typography_test.dart 报 lib/vps2vpn/kit.dart:151–152 的 fontSize/fontWeight 不符合继承的 AppTextStyle 规范。vpsText 目前只接收静态 VpsPalette，AppTextStyle.custom 需要 BuildContext。为了一个样式门禁向静态 palette 缓存 context 会引入生命周期/主题错误，单纯排除该文件又会放宽门禁。本轮保留此失败；需要统一自有设计套件和继承主题的契约，不能把它归因网络或核心运行故障。

### 其他边界

- HTTP 订阅与已有关闭 TLS 校验的用户设置仍有传输信任风险；本次没有实现 pin/CA 带外分发、轮换和存量迁移。
- Core 拒绝应用配置时仍走现有默认配置回滚；磁盘保留上次有效配置不等于运行路由也保留旧配置。
- PAC 外部覆盖检测、真实注册表权限、TUN、移动端切网、完整 Windows/macOS/iOS/Android release 和吞吐/时延/内存基准未完成。
- 全部自有 Go 生产代码和 12 个 lib/vps2vpn 模块已阅读，关键继承 profile/action/desktop IPC/Helper 调用链已追踪。大量继承 UI、原生平台和上游依赖尚未逐文件逐行全部审完，不能将本轮表述为整个大型 fork 已无遗漏。
- 后续原生服务路径权限、面板数值边界等发现须以追加的具体证据与回归为准；候选问题未经完整调用链确认不计入已修复清单。
