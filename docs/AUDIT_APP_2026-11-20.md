## 订阅并发提交补充修复

APP-13 / 高：`providers/actions/profiles.dart:156-205` 在下载并写入文件以后才读取最新 profile metadata，旧下载可能覆盖已修改 URL、已编辑文件或第二次更新的内容；删除与已开始的 rename 也可能交错，重新生成已删除文件。

本次补充修改 `models/profile.dart`、`providers/actions/profiles.dart`、`common/file.dart`、`state.dart`，采用以下契约：

1. 模型在下载开始前登记每个 profile 的写意图，直接文件保存也登记新的意图。旧下载即使较晚返回，也不能重新取得提交资格。
2. 下载、解压、临时写入与核心校验不占用提交队列；正式 rename 及删除按 profile 的绝对文件路径串行执行。
3. Actions 在提交前检查请求 token、Ref 生命周期、实时 type/url/ageSecretKey；文件提交执行前及 Windows 重试前再次检查意图。写失败不会使队列保持失败态，完成与异常都会释放尾链和意图。
4. 删除首先撤销未完成写意图，再删除 metadata，正式文件删除通过相同队列执行。因此已经发出的 rename 完成后才删除文件；尚未提交的临时文件由 finally 清理。
5. 只有当前更新可以写回 metadata 并触发 apply；过时的网络错误、验证错误和取消信号不覆盖最新 UI 状态。首次导入仍允许先创建 metadata，再下载配置。取消是内部控制流，safeRun 不把它显示为错误。
6. 缺失文件自动恢复的 `checkAndUpdateAndCopy` 同样接受 canCommit，并在文件探测等待前后校验；`SetupAction._setupConfig` 检查选择、来源、Ref 和启停请求，过时恢复返回未应用结果，不写回旧 metadata、不继续推送旧配置。恢复 metadata 时保留等待期间的名称等编辑。
7. 补上独立复核指出的 `rust_api.stopSystemProxy()` 等待后意图校验，防止旧任务继续更新报告或启动 guard。

新增 `test/providers/profile_update_order_test.dart` 九个用例，用本地 HTTP 请求 gate 和验证 Completer 明确控制完成顺序，覆盖旧下载迟到、旧验证迟到、只编辑来源、验证中删除、Ref 销毁、新 profile 首次更新，以及缺失文件自动恢复期间来源编辑、切换选择、删除三种事件。模型测试再覆盖新文件编辑胜出、失败不阻塞下一次写、删除与活跃重试排队、UI 静默取消。**这些 13 个补充用例仍需以 CI 的实际运行结果为准。**


## 不可信数值边界补充修复

APP-14 / 中：原始 `models/profile.dart:35-61`、`vps2vpn/panel.dart:63,166-184`、`account.dart:141`、`home.dart:780-786`、`mine.dart:581-586`，以及继承 `widgets/subscription_info_view.dart`、`views/dashboard/widgets/profiles.dart` 直接转换或计算服务器给出的数值。

- `expire=8640000000001` 秒超过 Dart DateTime 的正边界一秒。它会作为有效 int 持久化，但后续界面每次 build 再乘 1000 并构造 DateTime，持续抛异常；`9223372036854775807 * 1000` 在原生 int64 下则回绕成 `-1000`，会把非法未来值误当成 1969 年的日期。
- 合法 JSON 数字 `quota_eff: 1e300` 可通过旧面板解析；账户页换算 GiB 时产生 Infinity，随后 round() 抛 UnsupportedError。面板的 AI 时间戳也可使整份成员信息解码失败。
- 两个合法 int64 流量计数求和会回绕；剩余量先做连续减法再 max(0, ...) 也不能阻止回绕成正值。负数和非有限浮点数未在面板计数入口过滤。

这些是基于已读取的 Dart SDK 数值/DateTime 契约和实际调用链确认的缺陷；本地 executor 不可用，修复的运行复现仍由新增 CI 回归完成，不声称已经在本地运行 Dart 重现。

修复用统一 helper 在时间戳转换前检查有限性和范围，复用 `SubscriptionInfo.expireDate` 于全部扫描到的订阅日期消费者；计数转换有界、非负，合计使用饱和加法，剩余量先比较再减。已有数据库中的异常 int 也由这些 getter 防护。无须变更持久化字段或生成模型。

未知状态与有效的无限状态分开：header 中存在但无效的 expiry 用既有 int 字段的 `-1` 表示未知；只有缺省或明确的 `0` 仍表示没有截止时间。越界日期显示“未知”，不显示无限期。非生成 `VpsMember` 的 quota 可空，`quotaBytes` 对无法表示的配额返回 null，账户页显示“quota unknown”；只有有效数值 `0` 才显示 unlimited。面板无效到期值另标记 `expiryUnknown`，AI 无效时间只省略该可选时间，不丢弃有效的账户或 AI 状态。

新增 13 个边界回归，包括 DateTime 两端及越界值、Infinity/NaN、非法计数、int64 求和、持久化异常 expiry、真实本地 HTTP 面板的极大数字，以及账户、紧凑订阅、订阅明细、dashboard 的实际 widget build。除已有测试外，数值回归分布在 `test/common/{datetime,num}_test.dart`、`test/models/profile_test.dart`、`test/vps2vpn/{panel,account}_test.dart`、`test/widgets/subscription_info_view_test.dart`、`test/views/dashboard/profiles_card_test.dart`。
